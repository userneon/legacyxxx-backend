## Open — decide or schedule

1. **One token for everything.** A game server's `.env` token carries every scope (`bans:write`, `admin:read`,
   `stats:write` …) and every plugin on the machine uses it. A leak of that file, or a flaw in any one plugin, lets
   someone ban or unban anybody and read the staff list. Per-plugin tokens with only the scopes each needs would limit this.
2. **Access token in `localStorage`** (`src/api/client.ts`). The backend also issues an httpOnly cookie. There is no XSS sink
   in the frontend today, so the risk is low, but a cookie-only session removes the whole class.
3. **Global rate limit applies to plugin routes.** 600 requests/min per IP, and all game servers share one IP. A few busy
   servers (ban sweep every 30 s, skins menu, kill feed, heartbeat) can approach it; a 429 means servers look offline
   and menus fail. Raise `API_RATE_LIMIT_MAX` or key the limit on the token for `/plugin/*`.
4. **Old endpoints read the whole table:** `/leaderboard`, `/players/leaderboard`, `/players/:playerId` load all of
   `player_stats` on every request (and Supabase caps a result at 1000 rows). The frontend does not use them; delete or paginate.
5. **Placeholder accounts fill the leaderboard** now that everyone gets an account. Consider listing only players with
   `matches_completed > 0`, or showing the zero-EXP ones separately.
6. **IP bans and shared IPs.** Internet cafés share one address, so one IP ban blocks everyone there. Prefer SteamID bans
   and use IP bans for a short time only.
7. **`adminplus/backend`** is the old API with RCON access and its own secrets. If it is not running, delete it
   (smaller attack surface, no unaudited dependencies); if it runs, keep it firewalled.
8. **No Content-Security-Policy** on the website. The new headers cover framing, sniffing and HSTS; a CSP needs a test
   pass because of fonts, Steam avatars and inline styles.
9. **Tests:** the frontend has no tests or lint script, the plugins have only the authorization tests, and nothing here
   was run on a live CS2 server. The in-game flows (ban menu, knife vote, DB-only bans) still need a real test.
10. **Backups:** this audit could not see whether Supabase point-in-time recovery is on. Check it before December 1.
11. **Small:** 7 database functions have a mutable `search_path` (advisor WARN); `ann_count` in the notify layout is never set
    (dead UI); `CLAUDE.md` says the browser only calls `/api/public/*`, but the site calls authenticated routes with the
    user's session — update the sentence.

## Manual steps after pulling

- Backend VPS: `cd ~/legacyxxx-backend && git pull && bash ops/deploy.sh` (always first: the plugins now need the new endpoints).
- CS2 VPS: `cd ~/legacyxxx-plugins && git pull && sudo ./scripts/cs2-host.sh deploy && sudo systemctl restart cs2@27015`.
- Frontend VPS: `cd ~/legacyxxx-frontend && git checkout -- package-lock.json && git pull && bash ops/deploy.sh`, then
  `sudo cp ops/nginx/legacyx-security-headers.conf ops/nginx/legacyx-frontend.conf /etc/nginx/snippets/ && sudo nginx -t && sudo systemctl reload nginx`.
  Copy both files together: the frontend snippet now includes the headers file, and `nginx -t` fails if it is missing
  (the running config stays untouched if that happens).
- Discord bot: pull and restart.
- Backend `.env`: `STEAM_WEB_API_KEY` must be set for names and avatars.
